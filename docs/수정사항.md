# 수정사항

작성일: 2026-05-29

## 1. 모델 변경

기존:

- `qwen2.5:7b`
- Qwen2.5 계열
- 2024년 공개 모델
- 로컬 Ollama 기반 실행

변경:

- `qwen35-9b`
- `Qwen/Qwen3.5-9B`
- Qwen3.5 계열 최신 모델
- 연구실 GPU 서버에서 vLLM으로 실행

요약:

```text
qwen2.5:7b + Ollama
-> qwen35-9b + 연구실 GPU 서버 vLLM
```

## 2. GPU 서버 연결

기존:

- Mac 또는 로컬 환경에서 모델 실행
- 모델이 없거나 성능이 부족하면 응답이 느리거나 실패 가능

변경:

- 연구실 GPU 서버에서 vLLM 서버 실행
- Mac에서는 SSH 터널로 GPU 서버에 연결
- 백엔드는 `http://127.0.0.1:8008/v1`로 요청

요약:

```text
로컬 모델 실행
-> 연구실 GPU 서버 모델 실행
```

주의:

- GPU 서버의 vLLM 터미널은 꺼지면 안 됨
- Mac의 SSH 터널 터미널도 꺼지면 안 됨
- AX Gate가 끊기면 다시 로그인 후 터널 재연결 필요

## 3. 자주 묻는 질문 SQL 처리

기존:

- 자주 묻는 질문도 매번 모델이 SQL 생성
- SQL은 생성되지만 실제 DB 조회에서 실패하는 경우 발생
- 원인: 잘못된 컬럼명, 존재하지 않는 테이블 조합, DB API 차단 키워드 등

변경:

- 자주 묻는 질문 6개는 검증 SQL을 직접 사용
- 실제 MES DB API에서 실행 확인한 SQL만 사용
- 자유 입력 질문은 기존처럼 모델이 SQL 생성

요약:

```text
FAQ 질문도 LLM이 SQL 생성
-> FAQ 질문은 검증 SQL 실행
```

적용된 질문:

- 이번 주 생산량을 라인별로 보여줘
- 오늘 불량률이 가장 높은 공정은?
- 지난달 설비 가동률 추이를 알려줘
- 작업자별 생산 실적을 비교해줘
- 이번 분기 납기 준수율은 얼마야?
- 최근 7일간 불량 유형별 현황

## 4. 불량 관련 스키마 보강

기존:

- 불량 관련 테이블 일부 컬럼 정보 부족
- 모델이 불량 유형/불량 이력 SQL을 만들 때 컬럼을 추측함

변경:

- `CIM_DEFECT`
- `CIM_DEFECTCLASS`
- `CIM_LOTDEFECT`

위 테이블의 주요 컬럼 정보를 추가했다.

요약:

```text
불량 테이블 스키마 부족
-> 불량 관련 테이블 컬럼 정보 보강
```

## 5. 통계 화면 시각화

기존:

- 통계 화면으로 이동하는 기능은 있었음
- 원본 데이터 표와 자동 차트 코드도 있었음
- 하지만 DB 응답 형식이 맞지 않아 시각화가 제대로 안 됨

변경:

- DB 응답 데이터를 통계 화면이 읽을 수 있는 형태로 변환
- 원본 데이터 표 표시
- 숫자 컬럼 기준 자동 막대 차트/파이 차트 표시

요약:

```text
통계 화면 이동 후 시각화 오류
-> DB 결과 기반 표/차트 표시
```

## 6. 통계 화면 이동 후 채팅 유지

기존:

- 통계 화면으로 이동 후 다시 채팅 탭을 누르면 이전 대화가 사라짐
- 탭 전환 시 채팅 컴포넌트가 새로 생성되는 구조였음

변경:

- 탭을 전환해도 기존 채팅 컴포넌트 유지
- 통계 화면에서 돌아와도 이전 질문/SQL/DB 결과 유지

요약:

```text
통계 화면 이동 후 채팅 초기화
-> 이전 채팅 상태 유지
```

## 7. 실제 MES DB 참고 후 SQL 생성

기존:

- 모델이 스키마/온톨로지만 보고 SQL 생성
- 실제 DB에 어떤 값이 있는지 모른 채 컬럼명이나 집계 방식을 추측
- SQL은 만들어지지만 DB 실행에서 실패하거나 의미가 어긋나는 경우 발생

변경:

- SQL 생성 전에 관련 테이블을 실제 MES DB에서 작게 조회
- 샘플 데이터, 날짜 범위, 주요 값을 확인한 뒤 SQL 생성
- 생성된 SQL의 테이블/컬럼이 스키마에 있는지 먼저 검증
- DB 실행 실패 시 오류를 모델에 다시 넘겨 SQL 수정 재시도

요약:

```text
스키마/온톨로지만 보고 SQL 생성
-> 실제 MES DB 샘플 확인 후 SQL 생성 + 검증/재시도
```

확인한 질문:

- 제품별 생산량을 보여줘
- 설비별 생산량을 보여줘
- 최근 7일간 불량 유형별 현황

## 8. 아키텍처 수정 상세

기존 흐름:

```text
사용자 질문
-> 스키마/온톨로지 검색
-> LLM이 SQL 생성
-> mes-api가 바로 실행
-> 실패하면 그대로 에러 표시
```

변경 흐름:

```text
사용자 질문
-> 스키마/온톨로지 검색
-> 관련 테이블을 실제 MES DB에서 샘플 조회
-> 샘플값/날짜범위/주요값을 프롬프트에 추가
-> LLM이 SQL 생성
-> 생성 SQL의 테이블/컬럼 사전 검증
-> 의미 검증(생산량은 CIM_LOT.QTY 기준 등) 적용
-> 실제 MES DB 실행
-> 실패 시 오류를 넣어서 SQL 수정 재시도
-> 성공하면 화면에 결과/분석 표시
```

역할 분담:

- `core/retriever.py`는 스키마/온톨로지 기반 관련 테이블을 찾는다.
- `core/db_context.py`는 실제 MES DB에서 작은 탐색 쿼리를 날려 참고값을 만든다.
- `routers/chat.py`는 SQL 생성, 검증, 재시도, 실행 흐름을 묶는다.
- `core/db_client.py`는 최종 SQL 실행을 mes-api에 위임한다.

요약:

```text
스키마만 참고하는 생성기
-> 스키마 + 온톨로지 + 실제 DB 샘플 + 검증/재시도 루프가 있는 생성기
```

## 9. 역할 기반 모호 제조 용어 해석

기존:

- "불량", "완료", "실적" 같은 단어를 모델이 문맥만 보고 해석
- 같은 질문이라도 품질팀/생산팀/관리팀 관점에 따라 SQL 의미가 달라질 수 있음

변경:

- 채팅 화면에서 사용자 역할 선택 추가
- 품질팀, 생산팀, 설비팀, 관리팀, 일반 역할 지원
- SQL 생성 전에 LLM이 모호 제조 용어와 후보 의미를 동적으로 생성
- 역할, 이전 대화 맥락, 검색된 스키마, 실제 DB 탐색 결과를 함께 보고 의미 선택
- 선택된 의미의 컬럼이 스키마에 실제 존재하는지 시스템이 검증
- 선택된 의미와 근거를 SQL 프롬프트에 추가
- 화면에는 "용어 해석" 근거를 표시

예시:

```text
품질팀 + "불량"
-> 스키마/DB 근거를 보고 불량률 후보가 타당하면 불량률로 해석

생산팀 + "불량"
-> 스키마/DB 근거를 보고 불량수량 후보가 타당하면 불량수량으로 해석

관리팀 + "불량"
-> 스키마/DB 근거를 보고 손실수량 후보가 타당하면 손실수량으로 해석
```

요약:

```text
모델이 애매한 제조 용어를 추측
-> 매 질문마다 역할/맥락/스키마/실제 DB 상태로 SQL 의미를 동적 결정
```

## 10. Google Cloud 배포 준비

추가:

- 백엔드 Cloud Run 배포용 `Dockerfile`
- 프론트 배포용 `UI/Dockerfile`, `UI/nginx.conf`
- vLLM GPU 서버 컨테이너 초안 `deploy/gcp/vllm/Dockerfile`
- Google Cloud 배포 메모 `deploy/gcp/README.md`

목표 구조:

```text
사용자 브라우저
-> 프론트 서버
-> FastAPI 백엔드
-> Google Cloud GPU vLLM 서버
-> MES DB API
```

운영 방향:

```text
연구실 GPU 서버 의존
-> Google Cloud GPU를 테스트할 때만 켜서 사용
```
